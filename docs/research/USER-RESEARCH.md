**What could not be fetched directly.** `reddit.com`, `news.ycombinator.com`, `g2.com`, `github.com` web pages, `community.n8n.io`, `docs.n8n.io` and most competitor websites were blocked (DNS or proxy) for page fetches. For those, the evidence is the summary a web search returned, not the page itself. Two sweeps (competitors, security/ops) ran after the shared search budget was used up, so they rely only on raw files from GitHub.

**Consequences for how to read this report.**

- Quotes are paraphrased and counts are snapshot values. For example, G2 tag counts (learning curve ~23 or ~39 reviews, cost control 17, pricing ~13, documentation ~10) come from different snapshots, and total G2 review counts ranged from 178 to 295.
- Many blog sources are written by competitors or vendors (Activepieces, Latenode, Orchestra, Emergent, GrowwStacks, StackOne, CredBridge, Albato). They are marked **(vendor)** where they carry a claim on their own.
- Pricing figures conflict between sources (self-hosted Business tier reported at $800/month and at $960/month after a May 2026 increase; AI builder credit allowances changed several times in 2026). We report the conflict rather than pick a number.
- Frequency labels (high/medium/low) are qualitative. They combine how many sweeps saw the issue and how often it appears on review sites. We never saw vote counts on n8n feature requests.
- "n8n does not have X" claims rest on the n8n docs and on keyword searches of the changelog up to 2.46.0. A missing changelog entry suggests a gap but does not prove it. n8n shipped a lot in 2026 (durable scheduler, workflow reviews, environments v2, end-user credentials, agents), so several items are marked as partial gaps.
- Not covered: Make, Gumloop, Lindy, Relay.app, Tray.io and Workato recipes have no primary-source findings. Make and Zapier appear only through comparison articles.

Sweep codes used in the tables below: **R** reviews, **F** forums, **Q** feature requests, **N** n8n inventory, **C** competitors, **S** security and operations.

### PP-01 Steep learning curve for non-coders; documentation too thin

This is the most common complaint on every review platform. Non-developers are pushed early into `{{ }}` expressions, the item/JSON data model and raw API concepts. Ease of use is n8n's lowest sub-score on Capterra and Software Advice. About ten G2 reviews also say the docs are too thin for advanced and production setups, which pushes users to the forum. Comparisons say Make hides more complexity behind defaults.

- G2 "dislike" tags: learning curve (~23 reviews in one snapshot, ~39 in another) and poor documentation (~10): [G2 reviews](https://www.g2.com/products/n8n/reviews), [G2 page 4](https://g2.com/products/n8n/reviews?page=4)
- Mapping complex JSON without a JavaScript background feels overwhelming: [G2 reviews and filters](https://www.g2.com/products/n8n/reviews_and_filters)
- Learning curve for non-coders named as the main drawback: [Product Hunt](https://www.producthunt.com/products/n8n-io/reviews?page=2)
- Ease of use is the lowest sub-score (4.1 Capterra, 4.0 Software Advice): [Capterra](https://www.capterra.com/p/198028/n8n-io/reviews/), [Software Advice](https://www.softwareadvice.com/bpm/n8n-io-profile/reviews/)
- Very steep without prior API or JavaScript knowledge: [Capterra](https://www.capterra.com/p/198028/n8n-io//reviews/), [StartupOwl 2026 review](https://startupowl.com/blog/n8n-review-pricing-features/)
- Make is simpler; n8n is not beginner-friendly: [Leanware](https://leanware.co/insights/make-com-vs-n8n), [Voiceflow](https://voiceflow.com/blog/n8n-alternative) (vendor)
- Docs lack real-world examples for advanced agents: [PeerSpot](https://www.peerspot.com/products/n8n-pros-and-cons), [The Digital Project Manager](https://thedigitalprojectmanager.com/it/tools/recensione-n8n/)

### PP-02 Vague errors and weak debugging tools

Errors arrive blank, generic ("UNKNOWN ERROR") or cryptic, and some nodes give little detail. In large workflows debugging is tedious, and a sub-workflow call is a black box. Users ask for breakpoints, stepping and drill-down into the child execution. In the Community edition, "Debug in editor" is a paid feature. Make is credited with letting users click any module after a test run to see its exact data.

- Debugging large workflows is tedious; errors vague: [G2](https://www.g2.com/products/n8n/reviews), [G2 page 3](https://g2.com/products/n8n/reviews_and_filters?page=3), [Capterra](https://www.capterra.com/p/198028/n8n-io/reviews/), [AWS Marketplace reviews](https://aws.amazon.com/marketplace/reviews/reviews-list/prodview-phou4jva26nvm)

### PP-03 No durable execution: crashes and timeouts lose state, retries re-run everything

When a worker crashes or a run times out, n8n keeps no record of which steps already ran. Retrying a dead execution starts from the beginning, so completed API calls run again (duplicate emails, charges, records). A large Code node restarts at item 1. Teams build their own progress tables, idempotency keys and dead-letter paths, or leave for Temporal-style engines. Long webhook-driven runs hit proxy timeouts (HTTP 524) because there is no built-in async job pattern. Retry policies with backoff and per-item error isolation are long-standing requests. n8n added suspension at node boundaries (2.43) and suspension of in-flight runs at worker shutdown (2.45), but no user-facing "resume from the failed node" ([changelog](https://raw.githubusercontent.com/n8n-io/n8n/master/CHANGELOG.md)).

- Team left after two years due to timeouts, memory limits and lost state on crashes: [Reddit mirror](https://reddit.sentinel-team.org/posts/1psaskx/snapshots/2025-12-23T08%3A11%3A06.135044Z)
- Two-hour workflow fails in queue mode despite a high timeout: [forum](https://community.n8n.io/t/help-workflow-2h-with-queues-workers-still-fails-on-timeout-what-am-i-missing/203447), [Railway forum](https://station.railway.com/questions/n8n-does-not-work-in-production-43bc9cd5)
- Retries duplicate earlier API calls; no retry-from-failed-step: [forum: partial failures](https://community.n8n.io/t/partial-failures-when-an-n8n-workflow-calls-multiple-apis/310338), [forum: centralized retry](https://community.n8n.io/t/best-practice-for-centralized-error-handling-and-retry-from-failed-step-in-production-workflows/300785), [retry guide](https://seo.rapidevelopers.com/n8n-tutorial/how-to-retry-failed-workflows-in-n8n)
- No automatic resume after a crash, unlike Temporal: [ZenML](https://www.zenml.io/blog/n8n-vs-temporal), [Metavert](https://metavert.io/compare/n8n-vs-temporal)
- Long webhooks hit 524 timeouts; async polling requested: [forum: 524](https://community.n8n.io/t/handling-long-running-n8n-workflows-solutions-for-browser-timeout-during-api-get-requests/44749), [forum: async polling](https://community.n8n.io/t/built-in-solution-for-async-polling-with-long-running-ai-workflows/125678)
- Retry policy with backoff; one bad item stops all items; retry settings ignored with Continue: [forum: retry policy](https://community.n8n.io/t/automatic-retry-of-workflows/5310), [forum: per-item errors](https://community.n8n.io/t/execution-stops-completely-for-all-items-when-there-is-an-error-in-one-item/6080), [GitHub #9236](https://github.com/n8n-io/n8n/issues/9236)

### PP-04 Pricing is unpredictable; self-hosted price shock; weak support

Reviewers like per-execution billing (see section 3) but find Cloud expensive at volume and plan limits arbitrary. The August 2025 move to execution-based plans led to complaints that polling triggers and chatbots use up quotas in days, and users are unsure what counts as an execution. The self-hosted Business tier (reported from $800/month, raised in May 2026) drew strong criticism, including a team that said its bill would rise from $50 to $10,400 per month. Trustpilot scores (~3.0/5) are far below G2 (4.7), driven by support, account access and billing friction, and Cloud workspaces have been down for days without an ETA.

- Expensive, especially for startups (~13 G2 reviews); much more expensive if you don't self-host: [G2](https://www.g2.com/products/n8n/reviews), [G2 reviews and filters](https://www.g2.com/products/n8n/reviews_and_filters)

### PP-05 Version control, diff and rollback are weak or paywalled

Git-based source control is a paid feature; the Community edition keeps about 24 hours of workflow history (5 days on Cloud Pro). Raw workflow JSON makes Git diffs unreadable: one member counted ~480 of 500 changed lines as position and ID noise. n8n's own docs say it cannot detect workflow conflicts and that a pull can overwrite local work. Users also report a two-branch limit and ask for finer-grained push and pull.

- No built-in version control; rollback hard: [Product Hunt](https://www.producthunt.com/products/n8n-io/reviews?page=1), [G2 reviews and filters](https://www.g2.com/products/n8n/reviews_and_filters)
- Native Git is basic and Enterprise-only: [LogicWorkflow](https://logicworkflow.com/blog/n8n-git-automation/), [Windmill comparison](https://www.windmill.dev/compare/n8n) (vendor)
- Unreadable JSON diffs; community-built visual diff tool: [forum](https://community.n8n.io/t/i-built-a-free-visual-diff-tool-for-n8n-workflows/283288); official visual compare tied to paid source control: [n8n docs](https://docs.n8n.io/source-control-environments/using/compare-changes)
- History retention by plan; settings changes do not create versions: [docs mirror](https://n8n-docs.teamlab.info/workflows/history/), [n8n-docs source](https://raw.githubusercontent.com/n8n-io/n8n-docs/main/docs/build/manage-workflows/view-change-history.md), [Activepieces](https://www.activepieces.com/blog/n8n-workflow-history-retention-and-how-to-restore) (vendor)

### PP-06 Team and governance basics are paywalled

The free Community edition lacks SSO (SAML, OIDC, LDAP), environments, Git, external secrets, log streaming, S3 binary storage, multi-main, custom variables and credential sharing across a team. Staff tell users to hard-code values in Set nodes in place of `$vars`. Self-hosters build community OIDC hooks, and some move to Windmill. There is no built-in record of who triggered a manual run unless you buy log streaming.

- Official list of excluded features: [n8n docs](https://docs.n8n.io/deploy/host-n8n/community-edition-features/), [n8n docs (older path)](https://docs.n8n.io/hosting/community-edition-features)

### PP-07 Multi-tenancy and per-customer credentials are do-it-yourself

Agencies usually run one isolated n8n instance per client, which multiplies containers, databases, backups and version drift. Credentials are bound to nodes statically, so serving many customers from one workflow means duplicating the workflow, or building a Switch node with hundreds of branches. Users have asked "for many years" to pick a credential by expression. n8n's end-user credentials (2026) cover OAuth only, with one account per user per template. Agencies also find client handoff messy: clients should not get raw editor access, and collecting API keys over email looks unprofessional.

- Instance per client; encryption-key loss risk: [forum: agency multi-tenant](https://community.n8n.io/t/how-i-handle-multi-tenant-n8n-for-agency-clients-isolated-instance-per-client-shared-updates/301614), [forum: multiple clients](https://community.n8n.io/t/self-hosting-whats-the-best-option-to-handle-multiple-clients/273127), [forum: white-label multi-tenancy](https://community.n8n.io/t/can-n8n-be-used-as-a-white-label-solution-supporting-multi-tenancy/8493)
- Dynamic credentials per tenant or per item: [forum: dynamic credentials thread](https://community.n8n.io/t/possible-to-do-multi-tenant-workflows-that-can-reference-credentials-dynamically/62218/17), [forum: expression in credential field](https://community.n8n.io/t/dynamic-credential-selection-via-expressions-for-multi-tenant-workflows/236158), [forum: "many years"](https://community.n8n.io/t/dynamically-select-credentials-in-nodes/68113), [forum: multi-user OAuth](https://community.n8n.io/t/how-to-implement-true-multi-user-oauth-in-n8n-without-individual-credential-entries/157748), [forum: per-customer Google](https://community.n8n.io/t/using-n8n-api-to-build-a-saas-with-per-customer-google-credentials-best-practices/239574), [CredBridge](https://credbridge.vercel.app/blog/n8n-workflow-duplication-agencies) (vendor)

### PP-08 License blocks SaaS, white-label and agency use

n8n moved from Apache 2.0 to the Sustainable Use License, which is not OSI open source. It forbids hosting n8n as a service and building apps in which end users connect their own accounts. Embedding needs a separately negotiated license reported at about $50K per year, with n8n branding. There is no agency tier. Self-hosting communities recommend MIT-licensed Activepieces for this reason. This gap is exactly what a multi-tenant, white-label platform fills.

- License terms and what is not allowed: [n8n fair-code docs](https://docs.n8n.io/faircode-license), [Sustainable Use License](https://docs.n8n.io/n8n-community-license/sustainable-use-license), [isitreallyfoss](https://isitreallyfoss.com/projects/n8n), [SSD Nodes](https://www.ssdnodes.com/learn/n8n-sustainable-use-license-explained), [Activepieces license guide](https://www.activepieces.com/blog/n8n-license-fair-code-community-enterprise-2026) (vendor)
- Paid SaaS on top of n8n needs a commercial agreement: [Pixeljets](https://pixeljets.com/blog/n8n-vs-code/), [dev.to](https://dev.to/alifar/the-real-limits-of-n8n-free-automation-what-you-need-to-know-before-shipping-to-production-59o6)

After a Merge node, `$('Node').item` can fail with "Can't determine which item to use"; users report this as a regression. Branches run one after another in canvas order, which surprises users who expect parallelism, and there is no clean fan-out/fan-in for N sub-workflows.

- [GitHub #35559](https://github.com/n8n-io/n8n/issues/35559), [forum: duplication](https://community.n8n.io/t/unexpected-data-duplication-in-loop-over-items-node/263239), [forum: connection order](https://community.n8n.io/t/how-to-merge-seperated-items-into-a-single-item/11686), [GitHub #25019](https://github.com/n8n-io/n8n/issues/25019), [forum: improve Loop Over Items](https://community.n8n.io/t/have-your-say-help-us-improve-the-loop-over-items-node/92570?tl=en)
- Parallel and async requests: [forum: Async Start/End](https://community.n8n.io/t/we-really-need-async-start-and-async-end-nodes/285100), [forum: parallel part](https://community.n8n.io/t/is-it-possible-to-run-a-part-of-the-workflow-in-parallel/60221), [forum: N sub-workflows](https://community.n8n.io/t/what-is-the-best-pattern-for-triggering-n-sub-workflows-in-parallel-and-resuming-main-workflow-when-all-complete/233446), [forum: async parallel](https://community.n8n.io/t/async-parallel-execution/229201), [n8n docs: execution order](https://docs.n8n.io/flow-logic/execution-order)

### PP-22 Concurrent editing overwrites work; permissions too coarse

n8n's docs warn that two people editing one workflow can overwrite each other. Users lost changes to another open tab. Autosave now locks the canvas read-only for the second editor, which generated version-history noise and a popular "disable autosave" request. Teams want real-time co-editing (competitor Dify has it), node-level locks, an execute-only role and control over who sees execution logs; custom roles are Enterprise-only and per project.

- [n8n docs: best practices](https://docs.n8n.io/user-management/best-practices/), [n8n blog: autosave](https://blog.n8n.io/announcing-autosave), [forum: reverted version](https://community.n8n.io/t/n8n-switches-my-workflow-to-an-older-version-w-o-me-doing-anything-bug/114622), [forum: disable autosave](https://community.n8n.io/t/disable-autosave-got-created/263825), [forum: UI requests](https://community.n8n.io/c/feature-requests/ui/8)
- Co-editing requests: [forum: collaborative editing](https://community.n8n.io/t/live-ai-workflow-builds-github-evaluations-collaborative-editing-support-request/125103), [forum: collaboration in community](https://community.n8n.io/t/collaborate-on-workflows-community-version/45483), [GrowwStacks](https://growwstacks.com/blog/n8n-auto-save-feature), [Dify docs](https://docs.dify.ai/en/use-dify/build/workflow-collaboration.md)
- Permissions: [forum: node-level permissions](https://community.n8n.io/t/feature-request-node-level-edit-permissions/286438), [forum: who sees logs](https://community.n8n.io/t/project-role-permission-for-viewing-execution-logs/296330), [n8n docs: custom roles](https://docs.n8n.io/administer/manage-users-and-access/set-permissions-and-roles-rbac/create-custom-roles)

### PP-23 Schedules: timezone surprises, no overview, no calendar rules

Wrong-time runs usually come from timezone settings: the self-hosted default is New York, every queue-mode worker needs the timezone set, and DST shifts runs. Users want a timetable of all scheduled workflows, the next predicted run, end dates, and business-day or holiday rules that cron cannot express. n8n added missed-run catch-up options in 2.36 ([changelog](https://raw.githubusercontent.com/n8n-io/n8n/master/CHANGELOG.md)).

- [Nordflux: timezone](https://nordflux.de/en/guides/configuring-cron-and-schedule-trigger-correctly-in-n8n-the-timezone-is-almost-always-to-blame), [missed runs not fired](https://madebyaime.pages.dev/blog/n8n-schedule-trigger/), [forum: cron not triggering](https://community.n8n.io/t/cron-node-not-triggering-workflow-at-scheduled-time/282847)
- [forum: schedule overview](https://community.n8n.io/t/overview-of-schedulers/53287), [forum: next run](https://community.n8n.io/t/schedule-trigger-next-run-and-time-management/73057), [forum: end date](https://community.n8n.io/t/feature-request-add-end-date-expiration-setting-to-schedule-trigger-node/223530), [forum: holiday rules](https://community.n8n.io/t/scheduling-with-date-restrictions/249823)

### PP-24 Code node limits (Python, packages on Cloud)

Cloud blocks external modules in the Code node, and Python on Cloud cannot import libraries. Self-hosters build custom images and allowlist modules by environment variable. The old Pyodide Python was slow and was removed in 2.0 in favour of task runners. Pipedream and Windmill let code steps import any npm or PyPI package.

- [n8n docs: Code node](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.code), [Nordflux: Python limits](https://nordflux.de/en/insights/n8n-python-code-node-grenzen), [forum: external JS libraries](https://community.n8n.io/t/is-n8n-planning-to-support-importing-external-javascript-libraries-directly-in-the-code-node/176017), [forum: npm packages](https://community.n8n.io/t/how-to-use-multiple-external-npm-packages/20861)
- Competitors: [Compare Atlas: Pipedream](https://compare-atlas-pages.pages.dev/compare/pipedream-vs-n8n), [LowCode Agency](https://www.lowcode.agency/blog/n8n-vs-pipedream), [Pipedream README](https://raw.githubusercontent.com/PipedreamHQ/pipedream/master/README.md)

### PP-25 Human-in-the-loop approvals are fragile

Approvals built with Wait pause indefinitely by default, so users add their own timeouts, reminders and cut-offs. The resume URL changes on partial executions, state depends on execution retention, and a Wait inside a sub-workflow called as an AI tool does not pass its waiting state back to the agent. Users want a proper approval inbox with SLAs and escalation.

- [Nordflux: HITL](https://nordflux.de/en/guides/human-in-the-loop-approval-steps-for-agents), [Pushary](https://pushary.com/fr/human-in-the-loop-n8n) (vendor), [forum: wait inside tool](https://community.n8n.io/t/slack-send-and-wait-for-response-ai-agent-uses-wrong-input/78421), [Temperstack](https://www.temperstack.com/learn/n8n/implement-human-loop-workflows/)

## 6. Security lessons from n8n CVEs

n8n is an active target. One expression-injection RCE is in the CISA Known Exploited Vulnerabilities catalog with active exploitation, and a botnet (Zerobot) targets n8n ([CVE-2025-68613 record](https://raw.githubusercontent.com/CVEProject/cvelistV5/main/cves/2025/68xxx/CVE-2025-68613.json), [CISA KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog?field_cve=CVE-2025-68613), [Akamai](https://www.akamai.com/blog/security-research/2026/feb/zerobot-malware-targets-n8n-automation-platform)). A report on the expression-injection RCEs and their KEV listing put unpatched instances at about 24,700 ([Lilting](https://lilting.ch/en/articles/n8n-cve-expression-injection-rce-cisa-kev)); other coverage: [cvefeed](https://v2.cvefeed.io/vuln/detail/CVE-2025-68613), [GCVE](https://db.gcve.eu/cve/CVE-2026-1470), [Ctrl Alt Nod](https://ctrlaltnod.com/news/critical-n8n-flaws-allow-remote-code-execution-attacks), [GHSA-v98v-ff95-f3cp](https://github.com/n8n-io/n8n/security/advisories/GHSA-v98v-ff95-f3cp). On two days in February 2026, at least eight n8n CVEs were published on each day, most needing patches on three release lines ([CVE-2026-25054](https://raw.githubusercontent.com/CVEProject/cvelistV5/main/cves/2026/25xxx/CVE-2026-25054.json), [CVE-2026-27495](https://raw.githubusercontent.com/CVEProject/cvelistV5/main/cves/2026/27xxx/CVE-2026-27495.json)). A workflow platform stores every credential a company uses, so one sandbox bug exposes all of them.

### 6.2 Design rules for our platform

1. **Expressions are never evaluated by `eval`, `new Function` or `node:vm`.** Our tree-walking interpreter (see `ARCHITECTURE.md`) must also deny prototype, constructor and `__proto__` access at the AST level, cap steps, time and memory per evaluation, and run a regression suite built from the bypass classes in CVE-2025-68613, CVE-2026-1470, CVE-2026-25049 and CVE-2026-27577.
2. **Data is never code.** Only templates written at design time are parsed as expressions. Values produced at runtime (form fields, webhook bodies, API responses, LLM output) are typed as data and are never re-parsed, whatever their first character (CVE-2026-27493).
3. **User code runs out of process.** Code nodes run in `isolated-vm` isolates inside a separate runner process (or container) with no secrets in its environment, no filesystem, network off by default, a non-root user and a read-only root. There is no "internal mode" and no "insecure mode" switch (CVE-2026-27495, CVE-2026-0863).
4. **No ambient secrets.** A credential broker hands decrypted values to a node only for the call that needs them. Buffers are zero-filled, `/proc` is unreachable, and secrets are redacted from logs, execution data and agent memory by default (CVE-2026-27496; [#22643](https://github.com/n8n-io/n8n/issues/22643); [#34622](https://github.com/n8n-io/n8n/issues/34622); n8n made redaction enforceable only in 2.23, [#30801](https://github.com/n8n-io/n8n/issues/30801)).
5. **No host filesystem or shell nodes in the SaaS.** No Execute Command, Read/Write Files from Disk, host SSH or host Git. Binary data lives in tenant-scoped object storage behind opaque IDs. A Git node, if offered, runs inside the sandbox with hooks and config writes disabled (Git CVEs, CVE-2025-57749, CVE-2026-25052).
6. **Every embedded interpreter is a sandbox boundary.** SQL-over-items, JSONata, template languages and similar engines run inside the same isolate with memory limits, never in the main process (CVE-2026-25056, CVE-2026-27497).
7. **Public ingress is a separate service.** Webhooks, forms and chat endpoints run in an ingress tier that never holds the database password or encryption keys, validates bodies against strict per-content-type schemas with size limits, and never lets callers name files (CVE-2026-21858).
8. **User-authored HTML is served from a separate, cookieless origin.** Forms, chat pages, webhook HTML responses, binary previews and rendered markdown use a sandbox domain with nonce-based CSP. MIME type is set by the server, never by a request parameter (CVE-2025-46343, CVE-2025-52478, CVE-2026-25051, CVE-2026-27578).
9. **One egress layer, SSRF protection on by default.** All node HTTP goes through a shared client that blocks private, loopback, link-local and metadata ranges at connect time, re-checks after DNS resolution and redirects, and enforces per-tenant allowlists. Credentials are bound to exact domains with no wildcard shortcuts (CVE-2026-25631; [SSRF docs](https://raw.githubusercontent.com/n8n-io/n8n-docs/main/docs/deploy/host-n8n/configure-n8n/security/enable-ssrf-protection.md)).
10. **Envelope encryption per tenant from day one.** Per-tenant data keys are wrapped by a KMS master key, every ciphertext carries a key ID, and rotation is routine and reversible. Workers never receive a master key ([key rotation docs](https://raw.githubusercontent.com/n8n-io/n8n-docs/main/docs/deploy/host-n8n/configure-n8n/security/rotate-encryption-keys.md); lost-key incident in [Orchestra](https://www.getorchestra.io/guides/n8n-reviews)). Prefer short-lived workload identity over stored long-lived cloud keys ([Windmill changelog](https://raw.githubusercontent.com/windmill-labs/windmill/main/CHANGELOG.md)).
11. **Third-party nodes are signed, pinned and sandboxed.** A reviewed marketplace with signatures; each node declares the credential types and domains it may use and gets only those; tenant admins allowlist packages; installs never build shell strings (supply-chain campaigns; CVE-2026-21893).
12. **A tenant admin is not a platform admin, and every editor is untrusted.** Assume authenticated users will attempt RCE; the sandbox, not RBAC, is the last line of defence.
13. **Auth is deny-by-default.** No path-suffix exemptions in auth middleware, one central redirect validator (same-origin or relative only), and SSO enforcement checked on every identity-changing API (CVE-2025-49592, [#5525](https://github.com/n8n-io/n8n/issues/5525), [#25330](https://github.com/n8n-io/n8n/issues/25330)).
14. **Per-tenant policy packs.** Node and credential type allowlists, MCP server URL allowlists for MCP client nodes, and data-group rules that stop mixing business and personal connectors in one workflow ([StackOne](https://www.stackone.com/blog/best-mcp-gateway-for-n8n/), [Power Automate DLP](https://raw.githubusercontent.com/MicrosoftDocs/power-automate-docs/main/articles/prevent-data-loss.md), [n8n node policies](https://raw.githubusercontent.com/n8n-io/n8n-docs/main/docs/deploy/host-n8n/configure-n8n/security/block-specific-nodes.md)).
15. **Resource limits are a security control.** Per-execution memory, CPU time, payload size and item count quotas stop one tenant from taking down shared workers ([n8n memory docs](https://raw.githubusercontent.com/n8n-io/n8n-docs/main/docs/deploy/host-n8n/configure-n8n/scaling/fix-memory-issues.md)).
16. **Patch fast on one release line.** SaaS-first with rolling, automatic updates; self-hosted partners get one supported line, not three ([CVE-2026-27495 fixed on three lines](https://raw.githubusercontent.com/CVEProject/cvelistV5/main/cves/2026/27xxx/CVE-2026-27495.json)).
17. **Audit everything in every tier.** Who ran, changed, published or exported what, and every policy block, in an append-only per-tenant audit log ([forum: who executed](https://community.n8n.io/t/is-there-any-way-to-know-who-has-executed-a-workflow/193342); n8n added audit events for policy blocks only in 2.43, see [changelog](https://raw.githubusercontent.com/n8n-io/n8n/master/CHANGELOG.md)).

### 6.3 Implications for our current architecture

- `ARCHITECTURE.md` already rules out `eval` for expressions, uses `isolated-vm` for code, and puts an SSRF check on node HTTP. Keep these, and add rule 3 (separate runner process with no secrets) because `isolated-vm` in the main process still shares memory and environment with the API.
- Leader election through a Redis lock is the area where n8n had most 2026 bugs: ghost triggers, lost waiting executions, silent publish failures ([#35066](https://github.com/n8n-io/n8n/issues/35066), [#39896](https://github.com/n8n-io/n8n/issues/39896), [#38431](https://github.com/n8n-io/n8n/issues/38431)). Prefer Postgres-held leases (`FOR UPDATE SKIP LOCKED`) for triggers, timers and waiting executions, with Redis/BullMQ only waking workers.
- `execution_data.state` as one JSONB blob repeats n8n's storage pattern (PP-20). Store per-node step records and move large payloads to object storage (NF-01, NF-19).

### Feature notes

**NF-01 Durable step checkpoints and resume from failed node.** Record every node run (inputs reference, outputs, status, attempt) as its own row in Postgres as soon as it finishes. A crash or deploy resumes in-flight runs from the last completed node; a failed run can be fixed and resumed from the failed node (optionally on a newer version), reusing earlier outputs. Failed runs sit in an "incomplete" list with resume, skip and discard actions, as in Make. _Why n8n lacks it:_ retries start from the beginning and users build their own progress tables ([forum](https://community.n8n.io/t/partial-failures-when-an-n8n-workflow-calls-multiple-apis/310338)); n8n only added engine-level suspension in 2026 ([changelog](https://raw.githubusercontent.com/n8n-io/n8n/master/CHANGELOG.md)). Competitors: [DBOS](https://raw.githubusercontent.com/dbos-inc/dbos-transact-ts/main/README.md), [Windmill](https://raw.githubusercontent.com/windmill-labs/windmill/main/CHANGELOG.md), [Make](https://nguyenthanhluan.com/glossary/incomplete-executions/).

**NF-02 Idempotency keys, retry policies, per-item isolation.** Side-effecting nodes get an automatic idempotency key (execution + node + item + attempt) passed to APIs that support it and recorded in a side-effect ledger so a resume never repeats a completed call. Workflows declare a retry policy (attempts, exponential backoff, jitter, honour Retry-After). One bad item is routed to an error output while the rest continue. _Gap:_ [forum: retry policy](https://community.n8n.io/t/automatic-retry-of-workflows/5310), [GitHub #9236](https://github.com/n8n-io/n8n/issues/9236), [Trigger.dev idempotency](https://raw.githubusercontent.com/triggerdotdev/trigger.dev/main/docs/idempotency.mdx).

**NF-03 Bulk replay.** Select failed runs by workflow, time range, status and error, name the incident, and replay them on the current version at a set rate, with progress and abort. _Gap:_ n8n retries one execution at a time ([changelog](https://raw.githubusercontent.com/n8n-io/n8n/master/CHANGELOG.md)); see [Inngest replay](https://raw.githubusercontent.com/inngest/website/main/pages/docs/platform/replay.mdx).

**NF-04 Spend guardrails and cost metering.** Every node reports usage (API calls, credits, LLM tokens with model price) to a metering stream. Budgets per workflow, tenant and end customer, with warn, pause and hard-stop actions; loop and call-count circuit breakers; per-flow execution quotas; a cost preview before a manual run; chargeback export for resellers. _Gap:_ the largest G2 dislike tag in one snapshot ([G2](https://www.g2.com/products/N8N/reviews)); n8n's budget guardrail covers only its Agents product ([changelog](https://raw.githubusercontent.com/n8n-io/n8n/master/CHANGELOG.md)).

**NF-05 Tenant-native multi-tenancy with credential slots.** Workflows reference a credential _slot_ (for example `google`) rather than a credential ID. At run time the slot resolves to the right credential for the tenant, sub-account or end user, or by expression per item. Works for OAuth, API keys and basic auth, with several accounts per user. Admins can share global connections to chosen sub-accounts. _Gap:_ n8n end-user credentials are OAuth-only, one account per template per user ([docs](https://docs.n8n.io/administer/manage-credentials/end-user-credentials)); agencies run one instance per client ([forum](https://community.n8n.io/t/how-i-handle-multi-tenant-n8n-for-agency-clients-isolated-instance-per-client-shared-updates/301614)).

**NF-06 White-label kit and embed SDK.** Custom domains with automatic TLS, theme tokens, logos, email templates and UI locale per tenant; an embed SDK with signed JWT user provisioning; hosted "connect your account" pages; live run status streaming for the reseller's own app. _Gap:_ embedding requires a ~$50K/year agreement with n8n branding ([Activepieces](https://www.activepieces.com/blog/n8n-white-label-cost-and-what-you-can-rebrand-2026)); white-labelling means forking the frontend ([docs](https://docs.N8n.io/embed/white-labelling/)); the editor ships in English only ([forum](https://community.n8n.io/t/set-up-a-tool-to-manage-translations/295500)).

**NF-07 Agency client portal.** A branded portal for end clients: read-only run history, on/off toggles, simple input forms, credential connect links, and monthly health reports per client. _Gap:_ [Latenode thread](https://community.latenode.com/t/why-selling-n8n-automation-services-is-challenging-for-freelancers/22417), [GrowwStacks](https://growwstacks.com/blog/how-to-deliver-n8n-automations-to-clients), [forum: agency plan](https://community.n8n.io/t/new-pricing-plan-for-agencies/247356).

**NF-08 Keyed flow control.** Per-workflow settings for concurrency limits keyed by expression (for example per customer ID), throttle, debounce, priority and singleton runs; fair queuing across tenants; routing to tagged worker pools; reserved capacity per tenant. Changes apply at run time without restarts. _Gap:_ concurrency is global and fixed at startup ([n8n-docs](https://raw.githubusercontent.com/n8n-io/n8n-docs/main/docs/deploy/host-n8n/configure-n8n/scaling/control-concurrency.md)); see [Inngest](https://raw.githubusercontent.com/inngest/website/main/pages/docs/guides/flow-control.mdx).

**NF-09 Shared rate limiter.** Rate limits declared per credential or host (token bucket in Redis shared by all executions), automatic Retry-After handling, and webhook rate limits that answer 429. _Gap:_ [n8n docs: rate limits](https://docs.n8n.io/integrations/builtin/rate-limits), [forum: webhook rate limit](https://community.n8n.io/t/rate-limit-on-webhook-node/60682).

**NF-10 Immutable versions and in-flight pinning.** Each publish creates an immutable version. A run stays on the version it started on, even if it waits for weeks, unless an operator migrates it. Node-level semantic diff (added, removed, changed, rewired; positions ignored) and one-click rollback in every tier. _Gap:_ history is 24 hours on Community and diffs are paid ([n8n-docs](https://raw.githubusercontent.com/n8n-io/n8n-docs/main/docs/build/manage-workflows/view-change-history.md)); see [Trigger.dev versioning](https://raw.githubusercontent.com/triggerdotdev/trigger.dev/main/docs/versioning.mdx).

**NF-11 Workflow-as-code.** A typed TypeScript SDK that round-trips with the canvas; a canonical serialization with stable IDs and layout stored separately so Git diffs show logic only; a CLI (pull, push, test, publish) and free Git sync. _Gap:_ [forum: visual diff](https://community.n8n.io/t/i-built-a-free-visual-diff-tool-for-n8n-workflows/283288), [Skool: n8n-as-code](https://www.skool.com/ai-automation-society/3-min-vs-15-min-why-i-switched-from-n8n-mcp-to-n8n-as-code), [Kestra](https://raw.githubusercontent.com/kestra-io/kestra/develop/README.md).

**NF-12 Workflow test suites.** Named test cases per workflow with fixture inputs and assertions on node outputs; HTTP record and replay; mock mode for AI tools; a CLI runner for CI; optional "tests must pass to publish". _Gap:_ [LogicWorkflow](https://logicworkflow.com/blog/n8n-workflow-testing/), [forum: test cases](https://community.n8n.io/t/workflow-unit-testing-with-test-cases/254023), [Workato SDK](https://raw.githubusercontent.com/workato/workato-connector-sdk/master/README.md).

**NF-13 Workspace forks.** Fork a project into a sandbox with its own credentials and storage prefix, test there, then compare and merge back. _Gap:_ [forum: no staging](https://community.n8n.io/t/how-do-you-review-n8n-enterprise-workflows-without-a-full-staging-environment/130164); see [Windmill](https://raw.githubusercontent.com/windmill-labs/windmill/main/README.md).

**NF-14 Step debugger.** Breakpoints, step over and step into for manual runs; open a sub-workflow call to see its exact child execution; inspect any item's lineage. _Gap:_ [forum: debugger](https://community.n8n.io/t/improved-debugging-feature-request/119339), [forum: drill-down](https://community.n8n.io/t/easy-access-to-sub-workflows-drill-down/52965).

**NF-15 Structured, actionable errors.** Every error carries a code, node, item index, expression path, a trimmed upstream payload and the HTTP request/response summary, plus a plain-language explanation and a suggested fix from an error catalog. _Gap:_ blank and "UNKNOWN ERROR" messages ([forum](https://community.n8n.io/t/n8n-blank-errors/118304), [forum](https://community.n8n.io/t/oauth2-access-token-not-refreshing/21984?tl=de)).

**NF-16 Guided data mapping and simple mode.** Field pickers that write expressions; a slash menu of functions inserted as pills with live preview and type errors; a plain-language reading of each expression; a simple mode that hides advanced options. _Gap:_ [G2](https://www.g2.com/products/n8n/reviews_and_filters), [Activepieces formulas](https://raw.githubusercontent.com/activepieces/activepieces/main/docs/flows/using-formulas.mdx).

**NF-17 Credential health center.** Scheduled credential checks, tracked expiry, alerts before expiry, configurable refresh triggers (401, 403, custom), an expiry handler workflow, and a list of the workflows that depend on each credential. _Gap:_ [Bashmatica](https://bashmatica.beehiiv.com/p/nodebridge-2-the-irish-goodbye-of-your-workflow), [forum](https://community.n8n.io/t/how-to-stop-n8n-credentials-from-expiring-every-week/254327).

**NF-18 Alerting and ops in every tier.** Alert rules for failure rate, latency, "no runs in N hours" (heartbeat), credential expiry and budget, routed to email, Slack or PagerDuty; tenant-wide default error workflow and retry policy; a per-tenant operations dashboard; OpenTelemetry and log export not tied to a plan. _Gap:_ [Witscode](https://witscode.com/blogs/n8n-monitoring), [forum: default error workflow](https://community.n8n.io/t/how-to-set-default-error-workflow-for-new-workflows/7598), [n8n-docs: monitoring](https://raw.githubusercontent.com/n8n-io/n8n-docs/main/docs/deploy/host-n8n/keep-n8n-running/monitor-n8n.md).

**NF-19 Execution data lifecycle.** Retention set per workflow and outcome (for example failures 30 days, successes 1 day); payloads in object storage with TTL while metadata stays; time-partitioned execution tables dropped by partition; storage use shown per workflow; execution export. _Gap:_ [Railway](https://station.railway.com/questions/n8n-on-railway-how-to-safely-clean-exec-43de2666), [forum: prune but keep](https://community.n8n.io/t/is-there-a-way-to-prune-old-executions-data-but-keep-executions/35713).

**NF-20 Streaming items and resource quotas.** Paged and streamed item processing with automatic chunking of large inputs, binaries streamed to object storage, and per-execution memory and CPU quotas that fail one execution loudly instead of crashing the worker. _Gap:_ [forum: OOM with no error](https://community.n8n.io/t/out-of-memory-error-while-processing-10k-15k-items-in-batches-no-error-shown-in-execution-self-hosted-docker-v1-123-4/278455), [n8n-docs](https://raw.githubusercontent.com/n8n-io/n8n-docs/main/docs/deploy/host-n8n/configure-n8n/scaling/fix-memory-issues.md).

**NF-21 Async webhook jobs.** A webhook can reply 202 with a job ID at once, expose status and result endpoints, and optionally call back or stream progress over SSE. _Gap:_ [forum: 524](https://community.n8n.io/t/handling-long-running-n8n-workflows-solutions-for-browser-timeout-during-api-get-requests/44749), [forum: async polling](https://community.n8n.io/t/built-in-solution-for-async-polling-with-long-running-ai-workflows/125678).

**NF-22 Webhook event inbox.** Durable storage of every inbound event, provider presets that verify signatures, deduplication, a delivery log and one-click replay against the current version. _Gap:_ [Trigger.dev webhooks](https://raw.githubusercontent.com/triggerdotdev/trigger.dev/main/docs/webhooks/overview.mdx), [Compare Atlas](https://compare-atlas-pages.pages.dev/compare/pipedream-vs-n8n).

**NF-23 Approval inbox.** A built-in inbox for human tasks with all, first, sequential and quorum approval modes, reminders, SLAs, escalation and timeouts; one-tap approval in Slack, Teams and email; usable from sub-workflows and agent tools. _Gap:_ [Pushary](https://pushary.com/fr/human-in-the-loop-n8n), [forum: wait inside tool](https://community.n8n.io/t/slack-send-and-wait-for-response-ai-agent-uses-wrong-input/78421), [Power Automate approvals](https://raw.githubusercontent.com/MicrosoftDocs/power-automate-docs/main/articles/get-started-approvals.md).

**NF-24 Event correlation.** A run can wait for an event that matches an expression (for example "reply from this customer") and can be cancelled when a matching event arrives; early signals are buffered. _Gap:_ not in n8n's changelog; see [Inngest](https://raw.githubusercontent.com/inngest/inngest/main/README.md), [Activepieces waitpoints](https://raw.githubusercontent.com/activepieces/activepieces/main/docs/install/architecture/waitpoints.mdx).

**NF-25 Reliable agent runtime.** Agent memory written transactionally so a tool call and its result are always stored together; per-tool error policy (retry, return error to the model, fail); structured-output repair; iteration, time and cost caps; tools classified as read or write, with writes requiring approval by policy; a step-by-step agent trace. _Gap:_ [GitHub #24397](https://github.com/n8n-io/n8n/issues/24397), [forum: tool calls error](https://community.n8n.io/t/tools-calls-error-on-ai-agent-node/280816?tl=es), [Zapier MCP rules](https://raw.githubusercontent.com/zapier/zapier-mcp/main/plugins/zapier/rules/zapier-lifecycle.mdc).

**NF-26 AI copilot as reviewable drafts.** The copilot edits existing workflows as a draft, shows a diff, validates the schema and dry-runs against mocks before a person publishes. Tenants can bring their own model key, so there is no credit cap. Exposed over a per-tenant scoped MCP server for coding agents. _Gap:_ [forum: 30 credits](https://community.n8n.io/t/i-took-the-starter-plan-i-receive-only-30-credits-for-n8n-ai-builder-instead-of-50/223381), [GrowwStacks](https://growwstacks.com/blog/n8n-ai-workflow-builder-review/), [Vantaige: MCP not scoped](https://vantaige.io/blog/n8n-mcp-claude-code-setup-guide-2026).

**NF-27 Parallel branches and scoped loops.** Explicit parallel branches with a join node, a for-each container with clear scope (no connection-order surprises), N-way sub-workflow fan-out with fan-in, and a view of each item's lineage with the exact break point when pairing fails. _Gap:_ [forum: Async Start/End](https://community.n8n.io/t/we-really-need-async-start-and-async-end-nodes/285100), [GitHub #25019](https://github.com/n8n-io/n8n/issues/25019), [GitHub #35559](https://github.com/n8n-io/n8n/issues/35559).

**NF-28 Rename-safe references.** Expressions are stored against stable node IDs and shown with display names, so renames (in the editor, API or MCP) never break references, including in code nodes. _Gap:_ [n8n-decanter release notes](https://github.com/buttjer/n8n-decanter/releases/tag/v0.9.0).

**NF-29 Reusable component library.** Save node groups as snippets, share a library of tested functions callable from code steps, and publish a workflow as a typed component (input and output schemas, promoted parameters) that appears in the node panel, with auto-generated form, API endpoint and MCP tool. _Gap:_ [forum: snippets](https://community.n8n.io/t/feature-request-save-and-reuse-node-patterns-or-snippets-node-snippets/216796), [forum: workflows as nodes](https://community.n8n.io/t/workflows-as-first-class-nodes/35887?tl=pt_BR).

**NF-30 Workflow and entity state.** Workflow-scoped variables that nodes can read and write during a run, and a durable key-value store per entity (for example one state object per customer) with no-code get, set and increment nodes; table row-change triggers. _Gap:_ [forum: workflow vars](https://community.n8n.io/t/add-the-ability-to-configure-workflow-level-variables-and-or-global-variables/27602), [Restate](https://raw.githubusercontent.com/restatedev/restate/main/README.md).

**NF-31 Schedule center.** One timetable of all schedules with last and average run time, a preview of the next N fire times, a timezone on every schedule with DST-safe rules, business-day and holiday calendars, end dates, overlap policy, jitter and backfill over a date range. _Gap:_ [forum: overview](https://community.n8n.io/t/overview-of-schedulers/53287), [Temporal schedules](https://raw.githubusercontent.com/temporalio/documentation/main/docs/encyclopedia/workflow/schedule.mdx).

**NF-32 Package-enabled code steps.** Per-tenant allowlists of npm and PyPI packages, resolved and pinned with lockfiles, available on hosted plans inside the sandbox. _Gap:_ [forum: external JS libraries](https://community.n8n.io/t/is-n8n-planning-to-support-importing-external-javascript-libraries-directly-in-the-code-node/176017), [n8n docs: Code node](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.code).

**NF-33 Multiplayer editing and fine permissions.** Real-time co-editing with presence and cursors, node-level locks (for example prompts and routing), an execute-only role, and a permission for viewing execution data. _Gap:_ [n8n docs](https://docs.n8n.io/user-management/best-practices/), [forum: node permissions](https://community.n8n.io/t/feature-request-node-level-edit-permissions/286438), [Node-RED](https://raw.githubusercontent.com/node-red/node-red/master/CHANGELOG.md).

**NF-34 Upgrade shadow runs.** Before a platform or node-version upgrade reaches a tenant, recent production inputs are replayed against the new version with side effects mocked, and output differences are reported. _Gap:_ [GrowwStacks: 2.0 breakage](https://growwstacks.com/blog/n8n-2-update-breaking-changes), [BREAKING-CHANGES.md](https://raw.githubusercontent.com/n8n-io/n8n/master/packages/cli/BREAKING-CHANGES.md).

**NF-35 Platform health panel and config doctor.** Worker heartbeats, queue depth, stuck-run detection and a startup check that all processes share compatible versions, keys and storage settings; available to self-hosting partners on every tier. _Gap:_ worker views are Enterprise-only and misconfiguration leaves jobs stuck ([Railway](https://station.railway.com/questions/n8n-executions-stuck-on-queued-starti-9d19c16c), [Latenode: Coolify](https://community.latenode.com/t/issues-with-worker-queue-configuration-in-self-hosted-n8n-deployment-on-coolify-platform/34009)).

**Plan policy (not a feature).** Users leave over paywalled basics (PP-06). Gate on scale, support and compliance, not on hygiene: Git sync, version history, environments, variables, secrets, SSO via OIDC, alerting and audit belong in the base tier ([Latenode thread](https://community.latenode.com/t/self-hosted-n8n-users-whats-your-experience-thinking-of-switching-to-alternatives/38723)). Keep billing per execution (section 3).

**New feature notes (NF-36 to NF-41).**

**NF-36 Hybrid runners and private connectivity.** Tenants install a small runner agent (Docker image, Helm chart or binary) inside their own network.
- The runner opens an outbound mTLS connection to our control plane, so no inbound firewall rule is needed.
- It takes only jobs tagged for that tenant's runner pool, receives credentials one step at a time from the broker, and streams step results back.
- Individual nodes can be pinned to a pool, for example "run this Postgres step on-premises".
- Paid add-ons: dedicated static egress IP addresses per tenant, and private links.

_Why n8n lacks it:_ shared, changing Cloud egress IPs and no hybrid execution, as described in PP-27. _Competitors:_
- Power Automate: [on-premises data gateway](https://raw.githubusercontent.com/MicrosoftDocs/power-automate-docs/main/articles/gateway-reference.md).
- Windmill: agent workers, which authenticate with a workload identity token since 1.841.0 (2026-10-18) ([changelog](https://raw.githubusercontent.com/windmill-labs/windmill/main/CHANGELOG.md), [README](https://raw.githubusercontent.com/windmill-labs/windmill/main/README.md)).
- Kestra: workers connect over gRPC and "can run in another region or inside a restricted network" ([README](https://raw.githubusercontent.com/kestra-io/kestra/develop/README.md)).
- Trigger.dev: [private networking over AWS PrivateLink](https://raw.githubusercontent.com/triggerdotdev/trigger.dev/main/docs/private-networking/overview.mdx).

_Architecture impact (decide in M1):_ the worker protocol must not need direct access to Postgres or Redis. Job leases and step results go over an authenticated API, as Windmill's remote agent workers do, and credentials stay behind the broker.

**NF-37 Tenant snapshots, point-in-time restore and portability.**
- Scheduled and on-demand snapshots of a whole tenant: workflows with every version, credentials re-wrapped to a recipient key, variables, data tables with their rows, settings, users and roles, and schedules.
- Point-in-time restore of a single workflow, credential or table.
- A 30-day trash.
- Export and import between tenants, between regions, or to a partner's self-hosted installation, so customers are not locked in.

_Gap:_ see PP-28. _Architecture impact:_ per-tenant envelope keys (security rule 10) make re-wrapping possible without plaintext exports.

**NF-38 Connector factory.**
- Import an OpenAPI 3 spec, a Postman collection or a set of cURL commands, and generate a declarative connector: operations, parameters, pagination, an auth preset and output schemas.
- AI helps with naming and descriptions, and a test-call harness checks each operation.
- Connectors are versioned and published to a private per-tenant catalog, and each generated operation is also an agent and MCP tool.

_Gap:_ the n8n changelog through 2.46.0 has no OpenAPI-based node generation (its OpenAPI entries concern the public API schema only). Windmill generates HTTP route triggers from OpenAPI (1.496.0), not connectors. The MIT-licensed Activepieces pieces (200+, [README](https://raw.githubusercontent.com/activepieces/activepieces/main/README.md)) could be a licence-compatible source to import. _Architecture impact:_ the declarative connector spec must be data (JSON), not code, so generated connectors run in the sandbox without a code review. _Evidence status:_ user demand is not yet verified (10.5).

**NF-39 Execution search and business-key tracing.**
- Each workflow declares business keys as expressions (for example the order ID or customer ID), stored on every run.
- Tenant-scoped search over keys, error text and, optionally, redacted payload fields.
- A "trace this entity" view across workflows and sub-workflows.
- Saved searches can feed bulk replay (NF-03).

_Gap:_ see PP-30. _Architecture impact:_ the index is fed from step records (NF-01), redaction is applied before indexing, and index retention follows NF-19.

**NF-40 Data residency and privacy operations.**
- Each tenant is pinned to a data region. Executions, binaries, credentials and logs stay in that region, and the control plane holds only routing metadata.
- Data-subject tools find, export or erase records by a subject key across executions, data tables, binaries and agent memory.
- A data-location report for DPAs.

_Gap:_ see PP-31. _Architecture impact:_ add a region column on the tenant and region-aware storage URIs in M1, even if multi-region ships in M3.

**NF-41 Platform policy hooks and admin event webhooks for resellers.**
- Typed, sandboxed policy hooks per reseller or tenant run before create, publish, activate, execute, credential creation and user invitation. Each hook can allow, deny, or change fields within declared limits.
- Signed outbound admin event webhooks report events such as workflow published, execution failed, quota reached and user added, for resellers' billing and CRM systems.

_Gap:_ n8n's external hooks are arbitrary JavaScript files on the host, loaded by environment variable. They are used to cap workflows and credentials and to count or block executions (10.2). That model cannot be offered to tenants on shared infrastructure.

### 10.4 Weak, outdated or contradicted claims

1. **PP-14 and NF-26, "AI builder credits cannot be topped up": outdated.** n8n Assistant credits can be topped up manually or automatically, with a monthly cap, on Cloud Starter and Pro ([docs](https://raw.githubusercontent.com/n8n-io/n8n-docs/main/docs/deploy/use-n8n-cloud/assistant-credits/top-up-assistant-credits.md)). Only the hidden legacy AI Workflow Builder page says to upgrade the plan. NF-26 should instead rest on bring-your-own key, per-tenant budgets and availability on every deployment: Assistant credits are not offered on Cloud Enterprise or self-hosted, and one balance is shared by the whole instance.
2. **PP-02, "Debug in editor is paid on Community": outdated.** The free Registered Community edition unlocks it ([compare editions](https://raw.githubusercontent.com/n8n-io/n8n-docs/main/docs/deploy/host-n8n/community-edition-features.md)).
3. **PP-13, "failed runs may not be saved by default": contradicted.** `EXECUTIONS_DATA_SAVE_ON_ERROR` defaults to `all` ([executions env vars](https://raw.githubusercontent.com/n8n-io/n8n-docs/main/docs/deploy/host-n8n/configure-n8n/basic-configuration/use-environment-variables/executions.md)). The source is a third-party tutorial.
4. **Section 4 and NF-06, "editor ships in English only": imprecise.** A locale setting with English fallback exists. What is missing is maintained translations and a translation workflow.
5. **PP-06 lists OIDC among the SSO features missing from Community.** n8n's own edition comparison names only SAML and LDAP. Check the pricing page before stating where OIDC sits.
6. **PP-03, "n8n keeps no record of which steps already ran": overstated.** The per-workflow "Save execution progress" setting stores per-node data; it is off by default and there is no user-facing resume. The conclusion (no resume from the failed node) still holds.
7. **PP-15 and NF-04, "'lacking in cost-control features' was the largest G2 dislike tag (17 reviews)":** this comes from one snapshot seen only as a search-result summary; the G2 page was never fetched. It is the main review evidence for a high-impact M1 feature, so re-check it.
8. **PP-14, "~18% of outputs mixed prose into JSON":** a single, low-provenance source (`n8nguide-com.pages.dev`). Treat it as an anecdote.
9. **PP-08, embed licence "near $50K/year":** both sources are competitors (Activepieces, Albato). **PP-04, the "$10,400/month" case:** from a forum hosted by a competitor (Latenode). **PP-10, "a lost key cost 40 workflows and six hours":** from a vendor blog (Orchestra).
10. **PP-09, "crashes near 100k rows on paid Cloud":** first sourced from a summary of a YouTube video. n8n's published Cloud RAM limits (640 MiB on Starter and Pro-1) now make it plausible, but it is still not a measured figure.
11. **Low-provenance mirrors and aggregators.** Several claims rest only on these sites: `reddit.sentinel-team.org`, `hn.jakechampion.name`, `redlib.hackliberty.org`, and `*.pages.dev` sites (`navigator-3qw`, `n8nguide-com`, `madebyaime`, `zeshaq`, `compare-atlas-pages`, `34a5e7bd.hackernews-40s`). Examples: the team that left after two years (PP-03), DAG execution and agent loops (PP-14), and missed schedule runs (PP-23). Confirm these on the original platforms.
12. **"n8n does not have X" claims** still rest on changelog keyword searches. In this pass, keyword searches found no entries for hybrid or private connectivity, search over execution content, GDPR erasure, prompt versioning or OpenAPI connector generation. A missing changelog entry is not proof.
